# Étape 9.4 — Téléchargement R2

Implémentée et testée le 27 octobre 2026, Windows. Base 6c235f0. Réalisation autorisée dans le lot explicite 9.4–9.6 ; ce constat technique ne prétend pas à une revue indépendante.

GET/HEAD /api/v1/downloads/:id/:version résout une identité D1 publiée et vérifiée, contrôle la clé et les révocations avant tout cache, vérifie taille et ETag attesté par HEAD puis GET conditionnel et transmet le corps avec un plafond en flux. Révocation : 410, indisponible : 404, remplacement divergent : 503 INTEGRITY_ERROR. MIME application/vnd.kortex.tool+zip, no-sniff, disposition attachment, digest et ETag explicites. Le détail courant conserve son DTO et son descripteur ; le header Link fournit l'URL de téléchargement. Le chargeur Web accepte ce MIME sans changer l'admission cryptographique.

Le cache public exige une revalidation à chaque accès : un long TTL immutable exposé directement contournerait la révocation D1. Les octets adressés par SHA sont immuables mais la décision de servir reste dynamique ; aucun cache CDN n'est ajouté devant elle. Le consommateur hôte vérifie le SHA et la signature ; l'ETag R2 n'est pas un SHA. Aucun énorme tampon n'est construit par la route de téléchargement.

Vérifications réussies : pnpm --filter @kortex/api test (3 tests DTO et 19 tests workerd/D1/R2), pnpm --filter @kortex/api typecheck. Quatre nouveaux tests : octets exacts du vrai R2 local, headers/HEAD/304/détail, objet absent/remplacé/archivé/révoqué y compris ancien ETag, grand flux synthétique 24 Mio paresseux en tranches 64 Kio sans arrayBuffer ni concaténation et routes/méthodes invalides. Le R2 synthétique existe exclusivement dans le test du streaming. Une première insertion répétée de clé de fixture a rencontré la garde d'immuabilité ; le seed utilise maintenant INSERT SELECT WHERE NOT EXISTS. Le dernier passage complet réussit : target/validation-9.4-tests.log. Aucun schéma gelé modifié, aucune livraison distante à cette étape.
